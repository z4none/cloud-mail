# 邮件会话线程设计

日期：2026-10-03

## 目标

让收件箱和详情页以 Gmail 风格展示邮件会话：同一会话中的收件邮件、站内回复和外部回信归为一组，收件箱显示一条线程摘要，详情页按时间展示完整往来。

## 线程识别

邮件表新增持久化 `thread_id`。

新邮件入库或发出时按以下优先级确定线程：

1. 使用 `In-Reply-To` 和 `References`（现有 `in_reply_to`、`relation` 字段）查找关联邮件并继承其 `thread_id`。
2. 若关联头缺失或对应历史邮件没有可用关联，使用同一用户、同一账户和规范化主题进行回退匹配。规范化移除 `Re:`、`Fwd:`、`回复:` 等回复/转发前缀。
3. 找不到候选时，以当前邮件创建新线程。

所有由系统发送的回复继承原邮件 `thread_id`，并保存可供外部回信引用的标准 `message_id`。主题匹配只作为回退，避免同主题不同账户误合并。

## 数据迁移

- 为 `email` 增加非空 `thread_id`，默认空字符串以兼容现有数据库。
- 增加按 `user_id`、`account_id`、`thread_id`、`email_id` 的索引。
- 初始化/迁移时为历史邮件回填线程 ID，按创建时间稳定执行。
- 迁移可重复执行，不改写已确定的线程 ID。

## API

- 邮件列表按线程聚合，返回线程最新邮件、邮件总数、未读数、参与者和线程 ID。
- 增加按线程读取完整消息列表的接口，结果按创建时间及邮件 ID 升序。
- 删除、星标、已读等操作仍以单封邮件为最小单位；列表聚合值在操作后重新计算。

## 前端

- 收件箱每个线程仅显示一行，包含主题、参与者、最新时间、未读数和消息数量。
- 打开线程详情后，按时间展示收到与发出的每封邮件；保留每封邮件原有附件、内容、回复和转发能力。
- 回复继承当前会话并在发送成功后刷新线程。

## 验证

覆盖以下场景：

- 标准 `In-Reply-To` / `References` 链。
- 外部邮件对站内发送邮件的回信。
- 站内邮件回复。
- 同主题但不同账户不合并。
- 缺失邮件头的历史主题回退。
- 线程未读数、排序、分页和单封删除。
