# Cloud Mail 安全与工程质量加固设计

日期：2026-10-03

## 目标

分两个阶段提升生产安全性与可验证性：

1. 安全修复：对象私有化、XSS 防护、SQL 注入修复、会话过期、限流、初始化凭证保护。
2. 测试工程：恢复真实测试命令，补充认证、权限、邮件、附件和安全回归测试，并接入 CI。

## 已确认的资源访问策略

所有对象均为私有资源，不兼容旧的公开 URL，包括：

- 普通邮件附件
- 邮件内嵌图片
- 登录背景和其他用户上传对象

新增统一受保护对象接口：

```text
GET /object/:key
```

接口要求 Authorization Token，校验对象归属后从 KV、R2 或 S3 读取对象。对象不存在返回 404，无权限返回 403，认证失败返回 401。删除 Worker 当前对 `/attachments/*` 和 `/static/*` 的公开直读逻辑。

前端通过带 Authorization 的 fetch 获取 Blob，并创建本地 blob URL；邮件 HTML 中的对象地址转换为受保护对象请求，避免直接暴露公开资源 URL。

## 阶段一：安全修复

### SQL 注入

将 `public-service.js` 批量创建用户中的动态 SQL 全部改为参数绑定。用户、账户写入使用明确的批量事务流程，并为输入字段做邮箱、角色和长度校验。

### 邮件 HTML

渲染前使用 HTML sanitizer，删除脚本、事件属性、iframe、表单和危险协议。保留必要的邮件排版、图片和链接能力。所有邮件 HTML 资源经过资源 URL 转换后再渲染。

### 会话

JWT 设置显式过期时间；KV 会话保持一致 TTL。注销、改密、封禁、删除用户时清理相关会话。验证 Token 时严格检查 payload 结构、算法、签名和过期时间。

### 限流

对登录、注册、公开 API 和 OAuth 入口增加基于 KV 的 IP/账户限流，并返回统一错误码。限流实现抽为独立服务，便于测试。

### 初始化凭证

初始化接口不再通过 URL 暴露 JWT Secret，改用受保护请求头或一次性初始化凭证，并避免将凭证写入访问日志。

## 阶段二：测试工程

- `package.json` 的 test 脚本改为 `vitest run`。
- 修复 Vitest/Wrangler 配置路径。
- 移除 Hello World 快照测试。
- 增加 JWT、会话、权限、SQL 注入回归、对象越权、对象不存在、邮件 HTML 清洗和限流测试。
- 增加邮件收件、附件归属、普通附件与内嵌图片访问测试。
- 前端执行构建检查，后端执行单元及 Workers 集成测试。
- CI 阶段阻断测试或构建失败。

## 错误处理

统一返回 401、403、404、409、429 和 500 语义；服务端日志记录请求 ID、错误类别和资源类型，不记录密码、Token、初始化凭证或邮件敏感内容。

## 验收标准

1. 未认证或越权请求无法读取任意对象。
2. 邮件中的脚本和事件处理器不会执行。
3. 批量创建用户无法通过输入改变 SQL 语义。
4. JWT 和 KV 会话都能按预期过期、注销和失效。
5. 登录、注册和公开 API 超过阈值会返回 429。
6. `pnpm test` 执行真实测试并通过。
7. CI 能验证后端测试和前端构建。
8. 旧公开附件 URL 不再可访问。
