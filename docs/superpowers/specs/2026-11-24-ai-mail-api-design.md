# AI 邮件接口设计

日期：2026-11-24

## 目标

管理员在后台配置一个 API token，并勾选允许访问的邮箱。持有该 token 的 AI 可以查看这些邮箱、检索和读取邮件、回复已有邮件，以及用这些邮箱发送新邮件。

## 已确认范围

- 只有一个系统级 token，不给每个用户单独签发。
- token 只能访问后台勾选的邮箱，不能访问系统中的其他邮箱。
- AI 可以查询当前 token 能收取的邮箱列表。
- AI 可以检索、读取、回复，也可以主动发送新邮件。
- 第一版不上传、不下载附件，只在读取邮件时返回附件文件名。
- 不提供删除邮件、修改用户、修改系统设置或访问对象存储配置的能力。

## 鉴权

- 在系统设置中生成 token。完整 token 只在生成或轮换时显示一次。
- 数据库只保存 token 哈希，不保存明文。
- 请求使用 `Authorization: Bearer <token>`。
- token 与现有网页登录 JWT、现有 `/public` token 分开。`/public` 仍保留其原有权限，不作为 AI 入口。
- 可轮换和作废。轮换后旧 token 立即失效。
- 单独限流，避免 AI 轮询占满普通用户的请求额度。

## 邮箱授权

- 系统设置用复选框选择允许的邮箱账号。
- 只列出系统内已存在的邮箱。
- 取消勾选后立即生效，后续请求不能再读取或代表该邮箱发信。
- 邮箱被删除时自动从授权列表移除。

## 接口

所有接口都要求有效的 AI token。邮箱参数必须属于该 token 的授权列表，否则返回 403。

- `GET /ai/accounts`：返回可收取的邮箱、账号 ID 和显示名称。
- `GET /ai/emails`：在授权邮箱中搜索。支持邮箱、关键词、未读状态、起始时间和游标。结果包含邮件 ID、会话 ID、发件人、收件人、主题、时间、未读状态和纯文本摘要。
- `GET /ai/emails/:id`：读取一封授权邮件及其所在会话。返回纯文本、HTML、附件文件名和回复所需的邮件 ID。
- `POST /ai/emails/:id/reply`：回复指定邮件。收件人默认是原发件人，主题沿用现有回复规则。
- `POST /ai/emails/send`：用一个授权邮箱发送新邮件。请求包含发件账号、收件人、主题和正文。

搜索和读取不自动把邮件标为已读。

## 发信规则

- 回复和发新邮件都调用现有发信流程。
- 保留域名权限、每日或累计发送次数、线程和 `Message-ID` 行为。
- 发件账号必须属于授权列表，并且属于该邮箱的实际用户。
- 发送次数记在该邮箱所属用户上，不绕过现有限制。
- 正文同时接受纯文本和 HTML。只提供纯文本时，服务端生成对应 HTML。

## 错误

- 鉴权失败返回 401。
- token 有效但邮箱或邮件不在授权范围内返回 403。
- 邮件不存在返回 404。
- 参数不合法返回 400。
- 发信服务返回的失败保留原始原因，不再伪装成无说明的 501。
- 响应使用稳定的英文 `message`，便于 AI 判断；管理界面文案继续走现有中英文 i18n。

## 实现边界

- 新增独立的 `/ai` 路由和鉴权中间件。
- token 哈希与授权账号 ID 保存在系统设置中。
- 系统设置增加生成、轮换、作废和邮箱勾选界面。
- 不修改现有网页登录、`/public` 接口和邮件接收流程。
- 第一版不提供附件内容、抄送、密送和邮件删除。

## 验证

- 无 token、错误 token 和已作废 token 均不能访问。
- token 只能列出、读取和代表被勾选的邮箱发信。
- 取消勾选后，原邮箱的读取、回复和发信被拒绝。
- 回复会进入现有发信流程，并带上原邮件的回复关系。
- 搜索不会改变未读状态。
- Worker 测试覆盖鉴权、授权范围和发信调用边界。
