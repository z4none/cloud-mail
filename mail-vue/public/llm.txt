# Cloud Mail AI API

Use this API to list authorized mailboxes, search and read mail, reply, and send new mail.
All paths below are relative to the deployment origin and already include the `/api` prefix.

## Authentication

Send the token configured in System Settings → AI access:

```http
Authorization: Bearer <token>
Accept: application/json
```

The token is shown only once when it is generated or rotated. Store it outside this file. Do not send it in the URL.

Every JSON response has this envelope:

```json
{ "code": 200, "message": "success", "data": {} }
```

On failure, the HTTP status matches `code` and `message` explains the reason. Read `message`; do not treat every failure as an empty 501.

| HTTP | Meaning |
| --- | --- |
| 401 | Missing, wrong, or revoked token |
| 403 | The mailbox or email is outside this token's allowlist |
| 404 | Email does not exist |
| 400 | Invalid recipient, missing subject, or missing body |
| 422 | The mail provider rejected the message. Use `message` |
| 429 | More than 60 requests per minute from the same IP |

Searching or reading does not mark mail as read. There is no delete, attachment download, CC, or BCC in this API.

## 1. List mailboxes

`GET /api/ai/accounts`

No query parameters. Returns only mailboxes checked for this token.

```json
{
  "code": 200,
  "message": "success",
  "data": [
    { "accountId": 1, "email": "hi@example.com", "name": "Hi" }
  ]
}
```

Call this first. Use `accountId` for later searches and new messages. An empty array means no mailbox is authorized.

## 2. Search mail

`GET /api/ai/emails`

| Query | Required | Description |
| --- | --- | --- |
| accountId | no | Limit to one authorized mailbox. Omit to search all authorized mailboxes |
| keyword | no | Matches subject, sender name, or sender email. Maximum 100 characters |
| unread | no | `1` or `true` returns unread mail only |
| since | no | Inclusive lower bound on `createTime`, ISO-8601 |
| cursor | no | Pass the previous response's `nextCursor` to get older mail |
| limit | no | Page size, 1–50. Default 20 |

Results are newest first. `text` is a plain-text preview of at most 280 characters. `html` is not included.

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "emails": [
      {
        "emailId": 100,
        "accountId": 1,
        "threadId": "thread-id",
        "sendEmail": "person@example.com",
        "name": "Person",
        "subject": "Invoice",
        "recipient": "[]",
        "createTime": "2026-11-24 12:37:00",
        "unread": 0,
        "type": 0,
        "text": "Preview"
      }
    ],
    "nextCursor": 80
  }
}
```

`nextCursor` is `null` when there are no older messages. `unread` is `0` for unread and `1` for read. `type` is `0` for received and `1` for sent.

## 3. Read one email and its conversation

`GET /api/ai/emails/{emailId}`

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "email": {
      "emailId": 100,
      "accountId": 1,
      "threadId": "thread-id",
      "from": { "name": "Person", "email": "person@example.com" },
      "to": "[{\"address\":\"hi@example.com\",\"name\":\"\"}]",
      "subject": "Invoice",
      "text": "Full plain text",
      "html": "<p>Full HTML</p>",
      "unread": 0,
      "type": 0,
      "createTime": "2026-11-24 12:37:00",
      "attachments": [
        { "filename": "invoice.pdf", "mimeType": "application/pdf", "size": 12000 }
      ]
    },
    "thread": []
  }
}
```

`email` is the requested message and includes full `text`, `html`, and attachment filenames. Attachment bytes cannot be downloaded. `to` is a JSON string.

`thread` contains the other messages in the same conversation, oldest or stored order, with full `text`. Their `html` is empty and their `attachments` are empty. Use `emailId` from either object when replying to a specific message.

## 4. Reply

`POST /api/ai/emails/{emailId}/reply`

`Content-Type: application/json`

```json
{
  "text": "Thanks, I received the invoice.",
  "html": "<p>Thanks, I received the invoice.</p>",
  "subject": "Re: Invoice"
}
```

`text` or `html` is required. If `html` is omitted, it is generated from `text`. The recipient is always the original sender of `{emailId}`. Do not send a `to` field; it is ignored. If `subject` is omitted, the server uses `Re:` plus the original subject with reply or forward prefixes removed.

Sending uses the mailbox that received the original message and counts against that mailbox owner's send quota.

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "emailId": 101,
    "threadId": "thread-id",
    "messageId": "<id@example.com>"
  }
}
```

## 5. Send a new email

`POST /api/ai/send` is not valid. Use:

`POST /api/ai/emails/send`

```json
{
  "accountId": 1,
  "to": ["person@example.com"],
  "subject": "Hello",
  "text": "Plain text body",
  "html": "<p>Optional HTML body</p>"
}
```

`accountId` must be one of `GET /api/ai/accounts`. `to` may be one email string or an array of email strings. `subject` is required. `text` or `html` is required. No attachments can be uploaded.

The success `data` shape is the same as reply: `emailId`, `threadId`, and `messageId`.

## Recommended loop

1. `GET /api/ai/accounts`.
2. `GET /api/ai/emails?accountId={accountId}&unread=1`.
3. For each `emailId`, `GET /api/ai/emails/{emailId}` and read `email.text` or `email.html`.
4. Reply with `POST /api/ai/emails/{emailId}/reply` only when a reply is intended.
5. If `nextCursor` is not null, repeat the search with `cursor={nextCursor}`.
